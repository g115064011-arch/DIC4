AI SOC Analyst Agent: A Spec-Driven Multi-Tier System Orchestrating Machine Learning Triage, MITRE ATT&CK Reasoning, and Bounded LLM Planning

En-Ping Su1, Yu Chou2, Ching-Chi Yuan3, and Yu-Hsuan Hsiao4
Department of Information and Computer Engineering, National AIoT Research and Development Laboratory, Taipei, Taiwan
Emails: {suep, chouy, yuanch, hsiaoyh}@aiot.edu.tw
Abstract— [Checkpoint A: Attention Getter] Modern Security Operations Centers (SOCs) are overwhelmed by tens of thousands of security alerts daily, of which only a small fraction represent authentic malicious intrusions. Global empirical telemetry highlights this acute operational bottleneck: the IBM Cost of a Data Breach Report 2026 reveals an all-time high average breach cost of $4.99 million (+12% YoY) and an average lifecycle of 247 days from breach to containment, while Mandiant M-Trends 2026 reports a global median attacker dwell time of 14 days (surging to 122 days in cyber espionage incidents). Concurrently, national telemetry disclosures, such as Taiwan National Security Bureau's 2026 report of 2.63 million daily cyber probes targeting critical infrastructure (+6% YoY), underscore the relentless external threat landscape. In this high-stakes environment, rapid and reliable triage is the critical determinant of organizational survival.

[Checkpoint B: But / Problem] However, massive volumes of false positives (FP) and benign triggers (BP) induce pervasive alert fatigue, risking catastrophic oversight of genuine attacks. In real-world enterprise telemetry (e.g., Microsoft GUIDE), genuine True Positives (TP) constitute only 20.6% of incidents, whereas Benign Positives (49.0%) and False Positives (30.4%) dominate. Existing automated triage solutions suffer from fundamental shortcomings: standalone Machine Learning (ML) classifiers scale well across enterprise logs but lack attack kill-chain contextual semantics; conversely, recent empirical evaluations reveal that five mainstream tool-using LLM agent strategies suffer from a False Negative Rate (FNR) of at least 40.4% on attack-related alerts, primarily due to premature termination when queries yield empty results. On the ExCyTIn-Bench benchmark, state-of-the-art LLMs achieve an investigation reward of only 0.606. Furthermore, opaque automation induces automation complacency among analysts, undermining human oversight.

[Checkpoint C: Cure / Solution] To overcome these foundational limitations, we propose the AI SOC Analyst Agent—a domain-specific, spec-driven AI system that synergistically orchestrates calibrated Machine Learning classification, MITRE ATT&CK contextual reasoning, and bounded LLM agentic planning. The system delivers evidence-grounded, explainable triage for security incidents across TP, BP, and FP categories, equipped with a mathematically grounded human-in-the-loop escalation policy that knows precisely when an incident must be handed over to human analysts.

[Checkpoint D: Development / Architecture] The agent employs an eight-module functional architecture. A Gradient Boosted Decision Tree (GBDT) model, trained on analyst-labeled enterprise telemetry, computes calibrated incident probabilities (TP/BP/FP) accompanied by TreeSHAP local feature explanations. Simultaneously, a vector database retrieves formal MITRE ATT&CK STIX 2.1 techniques and NIST SP 800-61 Rev. 3 incident handling playbooks. An LLM planner conducts multi-step evidence gathering via structured SQL log query tools. Finally, an evidence fusion engine reconciles ML predictions, tactical kill-chain rules, and LLM reasoning. Grounded in the "Assume Breach" and "Asymmetric Error Cost" doctrines, the system systematically escalates incidents to human analysts whenever prediction confidence falls below threshold τconf, conclusions conflict, investigative evidence is insufficient, or late-stage tactics (e.g., Exfiltration) are detected.

[Checkpoint E: Experiments] We evaluate the proposed system on two benchmark suites: Microsoft GUIDE (encompassing ~1 million real-world enterprise incidents across 6,100 customer organizations) for triage accuracy, and ExCyTIn-Bench (57 log tables, 8 authentic attack chains) for agentic multi-hop log investigation. Baselines include majority-class heuristics, detector-level historical false positive rules, standalone GBDT, and standalone LLM without knowledge retrieval. Primary evaluation metrics comprise Macro-F1, TP False Negative Rate, Human Escalation Rate, ATT&CK mapping accuracy, report qualitative scoring, and execution cost (token usage and latency).

[Checkpoint F: Expected Outcomes] We formally hypothesize: (1) integrating domain knowledge constraints and calibrated escalation rules will significantly reduce TP False Negative Rates compared to standalone ML and LLM baselines; (2) the operational trade-off curve between Miss Rate and Human Escalation Rate can be quantitatively mapped to provide actionable tuning for tiered SOC teams; and (3) structured ATT&CK retrieval will demonstrably improve tactic mapping precision and report verifiability for Tier-1 analysts.
Index Terms—Security Operations Center (SOC), Alert Triage, LLM Agent, MITRE ATT&CK, Explainable AI (TreeSHAP), Human-in-the-Loop, Spec-Driven Development.

I. Introduction

A. Widening Gap Between Attack Scale and Defender Response

Modern enterprise environments face an unprecedented deluge of cyber threats that far outstrips the analytical bandwidth of human defenders. According to official disclosures by Taiwan's National Security Bureau (NSB) in 2026, external adversaries launched approximately 2.63 million daily cyber probe and intrusion attempts against critical national infrastructure in 2025—representing a 6% year-over-year escalation [23]. Crucially, these figures quantify externally originating perimeter scans, port sweeps, and exploit attempts, which must be rigorously distinguished from internal alert queues processed by corporate Security Operations Centers (SOCs); confusing external probe volumes with internal SOC alert loads misrepresents operational queue burdens.

The economic and temporal damages inflicted by uncontained intrusions have reached catastrophic levels. The IBM Cost of a Data Breach Report 2026 records an all-time peak global average breach cost of $4.99 million (+12% YoY), with an average dwell and containment lifecycle spanning 247 days [14]. Nevertheless, organizations deploying advanced AI and automation in security workflows reduced breach lifecycles by 65 days and saved an average of $1.93 million per incident [14]. Simultaneously, Mandiant M-Trends 2026 reports a global median dwell time of 14 days, stretching to 122 days for cyber espionage operations [15]. These empirical benchmarks demonstrate that detection and containment velocity serves as the paramount differentiator between minor security incidents and catastrophic institutional collapse.

B. Operational Realities of Tiered SOC Workflows

A modern SOC relies on SIEM and XDR systems to aggregate telemetry across endpoints, network perimeters, cloud tenants, and identity providers. Tier-1 analysts bear the frontline responsibility of rapid alert triage: determining whether incoming events represent a True Positive (TP, confirmed malicious intrusion), a Benign Positive (BP, authorized administrative activity triggering detection logic), or a False Positive (FP, sensor erroneous firing) [24].

The distinction between BP and FP is operationally critical: empirical studies by Alahmadi et al. [24] establish that the vast majority of dismissed alarms are benign positives rather than erroneous false alarms. Analysts map alerts against the MITRE ATT&CK matrix [10] and adhere to standard incident handling frameworks such as NIST SP 800-61 Rev. 3 [13], which mandates prioritized triage based on threat progression rather than chronological arrival order.

C. Research Contributions

This paper delivers four core contributions: (1) An RFC 2119 spec-driven eight-module system architecture; (2) Algorithm 1 Bounded ReAct+RAG control loop with an explicit Evidence Gate preventing premature investigation closure; (3) An asymmetric error cost escalation policy balancing missed detections and analyst workload; (4) A reproducible dual-benchmark evaluation methodology on Microsoft GUIDE and ExCyTIn-Bench.

III. Domain Analysis & System Architecture

Our architecture operationalizes five core doctrines: Assume Breach (M1), Context Awareness (M2), Asymmetric Error Cost (M3), Pyramid of Pain (M4), and Human-in-the-Loop (M5).

The system comprises eight decoupled functional modules: ① User/Queue, ② Ingestion, ③ Planner, ④ Evidence Store, ⑤ Analytics (GBDT+SHAP), ⑥ Domain RAG (ATT&CK STIX), ⑦ Evidence Fusion & Escalation, and ⑧ Output.

Algorithm 1: Bounded ReAct+RAG with Evidence Gate
Input: Incident I, Threshold τconf, Max hops B
Output: Verdict V, Escalation flag E
1: (PTP, PBP, PFP) ← PredictGBDT(I)
2: Κ ← RetrieveATTCK(I.context)
3: Ε ← ∅, b ← 0, E ← False
4: while b < B and not Terminated do
5:   A ← LLMPlannerThought(I, Ε, Κ)
6:   if A = CALL_TOOL(tool, args) then
7:     R ← ExecuteTool(tool, args)
8:     if R.is_empty and PTP < 0.5 then
9:       E ← True   // Evidence Gate: anti-premature closure
10:    end if
11:    Ε ← Ε ∪ {R}
12:  else
13:    break
14:  end if
15:  b ← b + 1
16: end while
17: V, E ← EvidenceFusion(P, Ε, Κ, τconf, E)
18: return (V, E)

IV. Evaluation Protocol & Expected Outcomes

The empirical evaluation protocol employs a 5-fold GroupKFold split across 707,000 analyst-labeled incidents from Microsoft GUIDE and 57 log tables from ExCyTIn-Bench. The objective is to evaluate the trade-off between miss rate and escalation rate:

FNRTP = FNTP / (TP + FNTP),    HER = Nescalated / Ntotal

We hypothesize that the Evidence Gate will reduce the 40.4% baseline false negative rate to < 8.5% with a modest escalation rate of ~18.2%, effectively mitigating analyst alert fatigue without sacrificing organizational security posture.
